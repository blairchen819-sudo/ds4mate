## 1. 背景与目标

### 1.1 背景
macOS 对游戏手柄的系统级支持长期以来非常薄弱：DualShock 4 在 Steam 之外几乎没有可用层。Eric 这类重度 macOS 用户希望**把手柄当遥控器用**——躺在沙发上操作 Mac 看视频、跑幻灯、做轻量级创意任务——但市面上的方案要么：

- 是 **Python 脚本 + 终端命令行**（如 `ps5-dualsense-mac-trackpad`），需要 venv、改代码；
- 是 **停更多年的开源 GUI**（Enjoyable 自 2014 年未维护）；
- 是 **功能臃肿的商业闭源软件**（ControllerMate / ControllerKeys），既不免费也不可审计。

### 1.2 产品目标
**DS4Mate** 是一款**原生 SwiftUI 菜单栏 App**，专注于"把 PS4 DualShock 4 变成 Mac 的鼠标 + 键盘 + 系统快捷键遥控器"，提供：

1. 蓝牙自动连接 PS4 DualShock 4（开箱即用，零命令行）；
2. 一套**合理且可改**的默认映射（参考 PS5 项目，移植并修正到 PS4 按键命名）；
3. 一个**可视化键位编辑器**，让用户点几下就能改任意按键映射；
4. 三个一键切换的预设（默认 / 媒体遥控 / 演示），覆盖 90% 用户的日常场景；
5. 完全开源（MIT），事件注入逻辑可审计。

### 1.3 非目标（明确不做）
- 不做 Xbox / PS5 / Switch / 第三方手柄支持（v1 范围外）。
- 不做 USB 有线连接（蓝牙是目标场景；如未来需求成立再议）。
- 不做宏录制、不做 JavaScript 脚本引擎。
- 不做云同步、不做账号体系。
- 不做自动更新、不做 App Store 发布（首版通过 GitHub Release + Homebrew Cask 分发）。

### 2.2 市场空白（机会窗口）

汇总差评 + 缺失功能，DS4Mate 的差异化定位有四个清晰方向：

1. **PS4 DualShock 4 专属 + 原生 SwiftUI 菜单栏 + 完全免费开源**的交集为空。
   - PadIO 是菜单栏 + 开源 + 免费，但**没有 GUI 编辑器**，用户必须写 JSON。
   - Recontrol 是 SwiftUI + 菜单栏 + 免费，但**不开源**且不针对 PS4。
   - Joystick Mapper 是 GUI + 付费，**单人开发者长期不更新**。
   - ps5-dualsense-mac-trackpad 是开源 + 免费，但**要命令行 + venv + 终端常驻**。

2. **"点按修改"的可视化映射编辑器** 是 GUI 映射工具的标配（Joystick Mapper、ControllerKeys 都有），但**开源 + 菜单栏** 项目里几乎没有。PadIO 强项是 JSON 热重载，但 Eric 这类"想自己改映射玩点花样但不想写 JSON"的用户被排除在外。

3. **可审计的事件注入逻辑**：商业闭源软件把 `CGEvent` 注入逻辑藏在二进制里，Eric 想"看清楚它在做什么"无从下手。MIT 开源 + 单一职责 = 天然的信任优势。

4. **预设驱动而非规则驱动**：ControllerMate 70+ 编程块适合工程师；Eric 想要的是"切到媒体遥控预设后手柄就当遥控器用"，不需要写规则图。

## 3. 目标用户画像

### 3.1 主要用户画像：Eric 型"Mac 重度玩家 + 手柄爱好者"

- **基本背景**：28–45 岁，男性居多；职业以开发者 / 设计师 / 技术写作者 / 独立创作者为主。
- **设备组合**：一台 MacBook 或 Mac Studio（Apple Silicon 优先）；至少一只 PS4 DualShock 4（从 PS4 退役后闲置，或专门为 Mac 买的）；可能还有 Apple TV 或客厅主机，习惯在不同房间用不同设备。
- **技术能力**：能读技术细节，能跑命令行但不享受跑命令行；对权限弹窗、Accessibility、菜单栏 App 概念不陌生。
- **使用场景**：
  - 客厅沙发上把 Mac 当机顶盒，用 DualShock 4 遥控视频播放、切换桌面、调音量。
  - 演讲 / 分享时用手柄翻 Keynote 幻灯片、切换 App、调激光笔（系统功能兜底）。
  - 离开工位时临时控制 Mac（切歌、暂停视频、触发快捷键），不必走回桌前。
- **核心痛点**：
  - 商业软件功能过剩、价格门槛、闭源不可审计；
  - 现存开源方案要么停更、要么要命令行；
  - "想自己改映射玩点花样"但**不想手写 JSON / 编程块**——要的是 GUI 点按即所得。
- **愿意付的代价**：愿意授予 Accessibility 权限（理解机制）；愿意花 10 分钟配一次；不愿付订阅。

### 3.2 次要用户画像

- **a11y 用户**：因手部活动不便需要手柄当主输入设备（与 InputConfig 用户重叠），他们看重预设的合理性而非深度定制。
- **客厅 Mac 用户**：把 Mac mini 当 HTPC 用，更看重媒体遥控预设和"开机即连"的体验。
- **中文 / 海外华人用户**：希望中文 UI，但 v1 不强求国际化（见 §8 非功能需求）。

RICE 定义（沿用团队基线）：
- **Reach**（1–10）：每季度受影响用户数（1=极少，10=全部）。
- **Impact**（0.25 / 0.5 / 1 / 2 / 3）：对单个用户的影响（3=巨大，0.25=微小）。
- **Confidence**（50% / 80% / 100%）：置信度。
- **Effort**（1–10 人月）：投入（1=半天，10=3 个月+）。
- **Score = (Reach × Impact × Confidence) / Effort**

### 4.4 可视化键位编辑器（详细交互）

> 用户原话："想自己改映射玩点花样"——这是 MVP 的灵魂功能。

**布局**：单窗格 + 一张 PS4 手柄正面示意图（SVG 图标 + 文字标签，按键用文字描述如"× 键"而非 emoji）。

**每个可交互按键**点击后展开右侧详情面板，包含：
- 当前映射动作（人类可读文字，如"鼠标左键"）
- 动作类型下拉：鼠标动作 / 键盘按键 / 修饰键组合 / 系统快捷键 / 媒体键 / 摇杆鼠标模式 / 滚动模式 / 禁用
- 参数面板（按动作类型显示）：
  - 鼠标动作：左键 / 右键 / 中键 / 双击 / 拖拽切换
  - 键盘按键：键盘捕获框（点一下后按任意键捕获）+ 修饰键勾选（Cmd / Option / Shift / Control）
  - 系统快捷键：预设列表（桌面、调度中心、App Exposé、Launchpad、截图…）
  - 媒体键：播放 / 暂停 / 上一曲 / 下一曲 / 音量 / 静音
- "恢复默认"按钮（仅恢复该按键）
- "应用到当前预设 / 保存为新预设"切换

**保存策略**：
- 改动即时生效，无需重启（与 Recontrol 对齐）。
- 改动写入 `~/Library/Application Support/DS4Mate/profiles.json`（具体路径由架构师决定）。
- 提供"撤销"按钮（仅本会话最近 10 步）。

**键盘 / 鼠标捕获**：编辑器内捕获用户按下的任意键 / 鼠标动作，自动识别为键码，无需用户手填。

### 4.5 附加功能（已实现，初版 PRD 未覆盖）

以下两项功能在开发中实现，但初版 PRD（§1–§10）未覆盖，在此补录。

**F18 桌面切换（Spaces）**
- 通过 macOS 调度中心（Spaces）切换虚拟桌面（见 `Sources/DS4Mate/Services/SpaceSwitcher.swift`）。
- 用途：配合预设在多个全屏 App / 桌面之间遥控切换。
- 依赖：辅助功能（AX）权限；运行时通过动态符号解析调用私有 CGS 接口（`CGSGetConnectionIDForPSN` / `CGSCopyDesktopWorkspace` 等），不链接私有框架。

**F19 千问（Qwen）语音控制**
- 一键开关通义千问（Qwen）语音通话、切换麦克风静音（见 `Sources/DS4Mate/Services/QwenVoiceController.swift`，动作枚举 `toggleQwenVoice` / `toggleQwenMic`）。
- 实现方式：经辅助功能（AX）读取千问窗口控件，定位并点击「语音通话」「麦克风」按钮；窗口不在当前桌面时自动跨桌面切换并切回原窗口。
- 约束：依赖千问客户端界面布局与辅助功能授权；千问改版或窗口不在当前桌面时可能失效（已做跨桌面切换兜底）。
- 隐私：仅做本地 AX 点击，不读取对话内容、不发起任何网络请求、不上传数据。

## 6. 验收标准（EARS 格式：Easy Approach to Requirements Syntax）

> 命名沿用 EARS 五种句式：Ubiquitous / Event-driven / State-driven / Optional / Unwanted。

### AC-1：蓝牙连接（Event-driven）
**When** 用户在 macOS 蓝牙设置中首次配对 DualShock 4（按住 Share + PS 进入配对模式），
**Then** DS4Mate 菜单栏图标在 5 秒内从"未连接"变为"已连接"状态（图标颜色 / 文字变化由 designer 定义，PRD 不硬编码颜色）；
**And** 用户按 × 键可在任意前台 App 触发鼠标左键。

### AC-2：自动重连（Event-driven）
**When** 用户将 DualShock 4 关机（长按 PS 键至灯灭）30 秒后再开机，
**Then** DS4Mate 自动重新建立连接，无需用户重启 App。

### AC-3：断开保护（Unwanted）
**When** DualShock 4 与 Mac 蓝牙连接丢失（手柄关机、超出范围、电量耗尽），
**Then** DS4Mate 在 3 秒内自动暂停所有事件注入，
**And** 菜单栏图标显示"已断开"状态，
**And** 不会留下"按键卡住"导致的虚假连续输入（如鼠标按钮卡住持续触发点击）。

### AC-4：默认映射生效（Ubiquitous）
**Where** 启用"默认预设"且 PS4 已连接，
**Then** §4.5 默认映射表中的每一条 PS4 按键 → macOS 动作的映射都按表格生效，无需任何额外配置。

### AC-5：可视化编辑器修改单键映射（Event-driven）
**When** 用户点击 PS4 示意图上的 × 键并选择新动作"音量减小"，
**Then** 该映射在 ≤ 1 秒内生效，无需重启 App 或重连手柄；
**And** 改动持久化到本地配置（下次启动 App 自动应用）。

### AC-6：预设切换（Event-driven）
**When** 用户在菜单栏下拉中点击"媒体遥控"预设，
**Then** 所有按键的映射立刻切换为媒体遥控预设定义的映射；
**And** 切换时不影响当前前台 App 的焦点（不抢焦点、不发送意外按键）。

### AC-7：退出 App（Event-driven）
**When** 用户点击菜单栏"退出 DS4Mate"或按 Options 键 1 秒，
**Then** DS4Mate 完全停止事件注入并退出，
**And** 退出后不残留任何后台进程或 LaunchAgent。

### AC-8：首次启动权限引导（State-driven）
**While** DS4Mate 首次启动且系统未授予 Accessibility 权限，
**Then** 主窗口（首次启动会显示主窗口，之后只显示菜单栏）顶部显示一条权限引导条，
**And** 引导条点击后跳转到"系统设置 → 隐私与安全性 → 辅助功能"并高亮 DS4Mate.app，
**And** 权限未授予时禁用事件注入功能（避免误导用户以为没生效）。

### AC-9：静默授权恢复（State-driven）
**When** 用户已在系统设置中授予 Accessibility 权限后切回 DS4Mate，
**Then** DS4Mate 在 ≤ 3 秒内检测到权限并启用事件注入，无需重启 App。

### AC-10：手柄电量提示（Optional，v1.1 候选）
**Where** PS4 DualShock 4 通过蓝牙连接，
**Then** DS4Mate 菜单栏下拉菜单中显示当前电量百分比（误差允许 ±20%）。

> AC-10 视实现复杂度决定是否进 MVP。若架构师评估电量读取需要私有 API 或不稳定，则降级为 v1.1。

## 7. 边界条件

| 场景 | 期望行为 |
|------|----------|
| **空状态** | 未连接手柄时，菜单栏下拉显示"等待 DualShock 4…"提示；编辑器灰色不可编辑 |
| **错误状态** | 蓝牙栈异常时显示具体错误文案（如"macOS 蓝牙服务不可用，请重启系统"），而非技术堆栈 |
| **加载状态** | 启动加载预设 / 加载配置时显示占位文字，不超过 500ms（本地配置读取应瞬时） |
| **边界值** | 摇杆死区（v1.1）默认 5%，可调 0%–30%；超 30% 拒绝保存并提示 |
| **并发** | v1 仅支持单手柄；检测到第二只 DualShock 时提示用户断开 |
| **离线** | App 离线可用，无网络请求；事件注入纯本地 |
| **权限拒绝** | 用户拒绝 Accessibility 后，引导条不消失，每 30 秒重新检测一次直到授予 |
| **手柄断开恢复** | 见 AC-3 |
| **休眠唤醒** | Mac 从休眠唤醒后，DS4Mate 自动重新连接（若手柄处于开机状态） |

## 9. 风险与待澄清

> 以下问题可能在评审中扩大或缩小 MVP 范围，需要 team-lead 协调用户 / 架构师决策。

### R-1：蓝牙栈选型
- macOS 上读取 DualShock 4 有两条主流路线：
  1. **GameController 框架**（系统原生，对开发者最友好，但 PS4 在某些 macOS 版本上的触摸板 / 陀螺仪 / LED 控制支持不全）；
  2. **IOBluetooth + IOHIDDevice**（更底层，能完全控制 HID 报告，但开发量大）。
- **待澄清**：Eric 对**触摸板当手势输入**或**自定义 LED 颜色 / 震动**有没有需求？v1 不做的话 GameController 足够；要的话需要走 HID。
- **影响**：如果选 GameController，v1 落地更快；如果选 HID，触摸板手势可作为 v1.1 卖点。

### R-2：Accessibility 权限策略
- macOS Sonoma (14) 引入"权限可被 App 单独吊销"机制。
- **待澄清**：DS4Mate 是否需要支持"权限失效时的自动降级"（例如回退到 SendKey 私有 API）？还是直接拒绝运行直到用户重新授权？
- **建议**：v1 直接拒绝运行直到用户重新授权（最安全、最透明）；降级方案 v2 再议。

### R-3：App Store vs 直分发
- Eric 偏好 GUI 点击式安装，抵触脚本。**但** App Store 上架需要沙盒，沙盒和事件注入存在历史兼容性争议。
- **待澄清**：v1 是走 Homebrew Cask + GitHub Release 直分发（推荐，省去沙盒烦恼）还是直接冲 App Store？
- **建议**：v1 走 Homebrew Cask + 直分发（与开源精神一致）；App Store 作为后续可选路线。

### R-4：UI 框架细节
- **待澄清**：菜单栏 App 使用 `NSStatusItem`（AppKit）还是 SwiftUI `MenuBarExtra`（macOS 13+）？
- **建议**：项目最低版本 macOS 13 已经定了，所以 `MenuBarExtra` 优先；编辑主窗口走标准 SwiftUI Window。

### R-5：默认映射的"硬约定"
- 参考实现里 PS 键映射为"显示桌面"——这个动作对部分用户是高破坏性的（不小心按到）。
- **待澄清**：默认预设里 PS 键是否映射到"显示桌面"？还是改为低破坏性动作（如"锁定屏幕"或"禁用"）？
- **建议**：默认预设 PS 键映射为"无（禁用）"，避免误触；"显示桌面"放在"演示 Preset"或编辑器内供用户自选。

### 10.1 参考映射表来源
移植自 `ps5-dualsense-mac-trackpad` 的 `default_button_map()` 函数（PS5 版），本 PRD 将其映射到 PS4 DualShock 4 的物理按键命名（× / ○ / □ / △ / L1 / R1 / L2 / R2 / L3 / R3 / D-Pad / PS / Share / Touchpad / Options）。具体按钮编号因 OS / 连接模式差异，使用时以 `pygame` 等库动态映射为准——DS4Mate 的实现需要架构师评估是否需要类似 `--debug` 模式。

### 10.2 术语表
| 术语 | 含义 |
|------|------|
| **CGEvent** | macOS CoreGraphics 框架提供的事件投递 API，用于注入鼠标 / 键盘事件 |
| **Accessibility 权限** | macOS "系统设置 → 隐私与安全性 → 辅助功能"，授权 App 控制电脑 |
| **GameController** | macOS / iOS 提供的游戏手柄抽象层 |
| **HID** | Human Interface Device，USB / 蓝牙输入设备的通用协议 |
| **NSStatusItem / MenuBarExtra** | macOS 菜单栏图标的两种实现（AppKit vs SwiftUI） |
| **预设（Preset）** | 一组绑定到手柄按键的映射集合，用户可在多个预设间切换 |
| **RICE** | Reach × Impact × Confidence / Effort，功能优先级排序方法 |
